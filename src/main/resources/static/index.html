charge no one twice.

Placing an order runs a saga: reserve stock → authorize payment → confirm. Transient payment failures are retried with backoff + jitter; only an exhausted retry budget — or a failure after the money moved — triggers compensation (release the stock, void the authorization). Idempotency keys absorb request retries, an atomic conditional decrement blocks oversell, every outcome travels a transactional outbox to Kafka, poison events park on a DLT, and one trace id follows the order across the async hop.

The amber scenarios inject faults through the X-Chaos header — the same API surface the recovery tests use.
